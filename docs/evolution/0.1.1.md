# Public research core 0.1.1

## Problem

The README presented the repository as an active correction-evaluation programme, while the author's own way of working had moved on: corrections are no longer logged one by one, and existing traces (commits, conversations, review comments) are analysed instead. The public description needed to match what is actually practised.

## Architecture and interface

No code, interface or behaviour change. The README (Chinese and English) now opens with the current five-step way of working and a short record of what changed, and describes the bundled code as the research core of the earlier approach. The `hcd` module and its API are unchanged.

## Decisions and alternatives

Keep the earlier research core public and runnable for reference rather than deleting it; state plainly that the author no longer uses the `hcd` scoring. Rejected: renaming modules or removing HCD from the code, which would break the published interface for a documentation-only change.

## Research hypotheses

Analysing traces that already exist may give fuller material at lower cost than asking for explicit per-correction logging. This is an observation from personal use, not a measured result; no before/after comparison has been published.

## Validation and limits

Synthetic regression tests and the publication boundary check pass unchanged. The README's recent finding (a three-line pre-start check for task purpose and scope) is reported as proposed, with its follow-up result not yet available.

## Next

Add follow-up results to the README as they become available; keep the code and documentation boundary unchanged unless the research core itself changes.
